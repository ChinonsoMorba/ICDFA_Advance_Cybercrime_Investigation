# CCSA108 - HTTPS Inspection Lab

## Part A: Practical Tasks

### Task 1: Plan the Deployment

**Gateway Version:** Check Point Quantum Security Gateway R82

**Requirement 1:** HTTPS Inspection requires the Security Gateway to intercept and decrypt HTTPS/TLS traffic before enabled security blades can inspect the traffic.

**Requirement 2:** Client devices must trust the HTTPS Inspection Certificate Authority (CA). If the CA is not trusted, browsers may display certificate warnings or block connections.

### Task 2: Enable HTTPS Inspection

HTTPS Inspection was enabled on the gateway. An outbound HTTPS Inspection CA certificate was selected, exported, and installed on the internal test host as a trusted root certificate.

### Task 3: Create the HTTPS Inspection Policy

Two outbound HTTPS Inspection rules were configured:

1. **Bypass Trusted Site**
   - Source: Internal_LAN
   - Destination/Site: Trusted site specified in the lab
   - Action: Bypass
   - Track: Log

2. **Inspect Outbound**
   - Source: Internal_LAN
   - Destination: Internet
   - Action: Inspect
   - Track: Log

### Task 4: Publish, Install and Verify

The HTTPS Inspection policy was published and installed successfully on the gateway. Verification activities were performed from the internal test host. Traffic inspection evidence could not be fully confirmed during testing.

### Task 5: Review the Global Settings

**Fail Mode:**
- Server-Side: Bypass all requests (Fail-Open)
- Client-Side: Bypass all requests (Fail-Open)

**Categorization Mode:**
- Hold – Block requests until categorization is complete.

**Server Validation Enabled:**
- Revoked server certificate (Validate CRL)

**Security Risk of Fail-Open:**
A Fail-Open configuration allows HTTPS traffic to pass without inspection when inspection cannot be performed, potentially allowing malicious encrypted traffic to bypass security controls.

# Part B: Theory Questions

## Section B1: Multiple Choice

**Q1. What does Outbound HTTPS Inspection do?**

A. Inspects encrypted traffic from internal clients to external servers.

**Q2. What does the gateway need in order to perform Inbound HTTPS Inspection?**

B. The target web server's digital certificate and private key.

**Q3. A web server uses Static NAT. Which IP address goes in the Destination column of its HTTPS Inspection rule?**

D. The original (pre-NAT) address.

**Q4. What is the recommended way to roll out HTTPS Inspection?**

B. Start with a small subset of traffic and expand gradually.

## Section B2: Short Answers

**Q5. Explain how Outbound HTTPS Inspection works.**

Outbound HTTPS Inspection creates two HTTPS connections. The client establishes a secure connection to the Security Gateway, and the Security Gateway establishes a separate secure connection to the destination web server. The gateway decrypts, inspects, and re-encrypts traffic between the two connections before forwarding it.

**Q6. Compare Outbound and Inbound HTTPS Inspection.**

| Inspection Type | Traffic Inspected | HTTPS Negotiation |
|---|---|---|
| Outbound | Internal users to external HTTPS sites | Uses the HTTPS Inspection CA certificate toward the client |
| Inbound | External users to internal web servers | Uses the server certificate and private key |

**Q7. Why must the outbound CA certificate be installed on client computers? Why should some trusted sites be bypassed?**

The outbound CA certificate must be trusted by client devices so that browsers accept certificates generated by the Security Gateway. Certain trusted or sensitive websites may be bypassed to avoid privacy concerns and application compatibility issues.

**Q8. Name three settings in the HTTPS Inspection Global Settings and say what each one controls.**

- **Fail Mode:** Determines whether traffic is blocked or allowed when HTTPS Inspection fails.
- **Categorization Mode:** Determines how traffic is handled while website categorization is being completed.
- **Server Validations:** Determines which certificate validation checks are performed on HTTPS servers.

## Section B3: Scenario

**Q9. After you enable HTTPS Inspection, every user sees a certificate warning, and one staff member complains that the company is reading their online banking. Give two actions you would take.**

1. Deploy and verify the HTTPS Inspection CA certificate on all client devices.
2. Configure bypass rules for trusted or sensitive sites such as online banking services.
